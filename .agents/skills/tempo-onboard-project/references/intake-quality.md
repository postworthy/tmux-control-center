# Intake Quality Checklist

Use this reference when project intent remains ambiguous after the initial
questions.

## Confirm

- One target user and their highest-value workflow.
- Observable v1 outcomes rather than a feature inventory.
- Explicit non-goals that protect the thin slice.
- Platform, delivery, privacy, security, legal, budget, and timing constraints.
- Existing behaviors that are truly compatibility requirements.
- What evidence will make the user call v1 successful.

## Adopt-Existing Distinction

- Inspect code and history before asking questions already answered by the
  repository.
- Present findings as hypotheses with confidence.
- Ask delta questions about product intent, production importance, hidden pain,
  intentional deferrals, and non-code constraints.
- Do not treat current implementation accidents as product requirements.

## Approval Quality

The user should be able to understand the proposed v1, trade-offs, exclusions,
and risks without software-engineering vocabulary. Approval of a vague idea is
not approval of implementation scope.
